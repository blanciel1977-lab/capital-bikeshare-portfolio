## 2. 결과 비교 — 인코딩 차이가 최우수 모델을 바꾼 사례

| 항목 | 이 프로젝트 | jskim414 |
|---|---|---|
| 최우수 모델 | 랜덤포레스트 (RMSE 4,308.82, R² 0.7556) | **Ridge(alpha=50)** (RMSE 3,987.3, R² 0.791) |
| `season`/`weather_code` 인코딩 | 숫자 그대로(서수) 투입 | **원-핫 인코딩** |

jskim414의 발견:
- 무규제 선형회귀에서 원-핫 인코딩된 `weather_code_26`(표본 3건뿐)의 계수가 **+2470**까지 튀는 다중공선성이 발생
- Ridge로 정규화하자 그 계수가 **+103**으로 안정화되면서 RMSE가 1.7% 개선
- 정규화된 Ridge가 결국 XGBoost·랜덤포레스트까지 이김

이 프로젝트가 앞서 세운 가설("다른 사람은 인코딩 방식 차이로 다른 모델이 1위가 될 수 있다")이 **실제 사례로 확인된 것**이다. 우리는 `weather_code`를 서수로 그대로 넣었기 때문에, 트리 모델이 값의 크기로 분기하는 데는 문제가 없었지만 선형모델(Ridge/Lasso 포함)은 원-핫이 아니면 이런 안정화 효과를 못 받는다.

## 3. 저희보다 더 파고든 지점

1. **`n_hours_observed` 변수를 의심하고 재검증**: 이 변수가 성능을 올려준 게 진짜 정보 때문인지, 아니면 결측일 과소집계를 우회로 보정하는 것뿐인지 확인하려고 온전히 관측된 날만 따로 떼어 재평가했다. 결과는 후자로 결론. 이 프로젝트는 이 변수를 QA 용도로만 쓰고 애초에 모델 입력에서 제외했는데, jskim414는 넣고 나서 효과의 정체를 파헤쳤다는 점이 다르다.
2. **크리스마스(2016-12-25) 개별 사례 분석**: 예측이 실제보다 20,766건 빗나간 걸 짚어, `is_holiday` 이진 변수가 "일반 공휴일"과 "연말 특수"를 구분 못 한다는 한계를 명시적으로 지적했다. 이 프로젝트의 예측 밴드 분석(밴드 밖 111일)은 개별 날짜까지 파고들지 않았다.
3. ~~**이상치 원인 변수 분해를 런던에도 적용**~~ — **(2026-08-20 완료)** jskim414는 "실기온(14일) > 습도(9일)" 순으로 보고했다. 이 프로젝트도 동일 방식(z-score 기준)으로 재현한 결과 `cnt`(10건, 27%) ≈ `wind_speed`/`hum`/`t2`(각 9건, 24%)로 **네 변수가 고르게 분포**해, 지배적 원인이 하나로 좁혀지지 않는다는 다른 결론이 나왔다(REPORT.md 5절, `src/19_anomaly_root_cause.py`, README.md 이상치 절). jskim414는 `cnt`를 원인 후보에서 뺐을 가능성이 있어 두 결과의 차이 자체도 "원인 후보 변수를 무엇으로 두느냐"가 결론을 바꾼다는 또 하나의 사례다.
4. **공휴일 Welch's t-test**: 공휴일 대여량이 유의하게 낮음(p=0.0014, -31.2%)을 통계적으로 확인 — 이 프로젝트는 워싱턴에서만 이 검정을 했고 런던에는 적용하지 않았다.

## 4. 이 프로젝트가 더 다루는 지점 (참고용, 우열이 아니라 차이)

- Isolation Forest 상위 이상치를 **외부 뉴스로 실제 사건과 대조**(2015-07-09 런던 지하철 파업) — jskim414 요약에는 이런 외부 검증 언급이 없음
- `log1p(cnt)` 변환으로 6개 모델 전체를 재비교해, 로그 변환이 최우수 모델 순위를 어떻게 바꾸는지 직접 실측(REPORT.md 4.5절)
- 워싱턴 프로젝트의 교훈(`yr` 외삽 불가, `t1`~`t2` 다중공선성, `is_weekend` 중복)을 런던 계획 단계에서부터 선반영

## 5. 확인 결과: 원-핫 인코딩 + Ridge 재실험 (완료)

`season`/`weather_code`를 원-핫 인코딩한 뒤 Ridge를 다시 돌려 직접 확인했다(`src/16_onehot_ridge.py`, `outputs/model/onehot_ridge_result.md`, REPORT.md 4.6절).

| 모델 | 인코딩 | RMSE | R2 |
|---|---|---|---|
| 랜덤포레스트 (기존 최우수) | 서수 | 4,308.82 | 0.7556 |
| Ridge (기존) | 서수 | 4,357.40 | 0.7501 |
| 선형회귀 (원-핫, 무규제) | 원-핫 | 4,247.43 | 0.7626 |
| **Ridge (원-핫)** | 원-핫 | **4,225.45** | **0.7650** |

**가설이 그대로 재현됐다.**
- 무규제 선형회귀에서 `weather_code_26`(눈, train 1일뿐) 계수가 **+2,453**까지 튐 — jskim414가 보고한 +2,470과 거의 일치
- Ridge 정규화 후 **+460**으로 안정화
- **원-핫 Ridge가 랜덤포레스트를 실제로 이김** (RMSE 4,225.45 < 4,308.82)

즉 "인코딩 차이가 최우수 모델을 바꾼다"는 결론은 다른 저장소 관찰이 아니라 우리 데이터로 직접 검증된 사실이 됐다. 다만 이 프로젝트는 `PREPROCESSING_NOTES.md`의 "원본 인코딩 유지"(다른 기간 데이터 재사용 목적) 원칙에 따라 메인 결과는 서수 인코딩 기준(랜덤포레스트)을 그대로 유지하고, 이 실험은 그 설계 선택이 성능에 미치는 영향을 투명하게 보여주는 보조 검증으로 남긴다.

## 6. 남은 확인 과제 (아직 미실행)

- `n_hours_observed`를 실제로 모델에 넣고, 온전히 관측된 날만 따로 떼어 효과가 진짜인지 재검증
- 크리스마스처럼 예측이 크게 빗나간 개별 날짜를 짚어 `is_holiday`의 한계를 구체적 사례로 보여주기
- 런던 데이터에도 공휴일 Welch's t-test 적용 (이상치 root-cause 분해는 위 3번 항목에서 완료)
