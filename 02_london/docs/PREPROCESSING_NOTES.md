# 런던 데이터 전처리 원칙 (시간별 → 일별)

`01_washington/docs/HOURLY_TO_DAILY_RULES.md`를 런던 데이터(`02_london/data/preprocess/london_merged.csv`)에 적용하기 위해 컬럼을 대조하고 확정한 원칙이다. **이 원칙에 따른 변환은 이미 실행 완료됐다** — 구체적인 컬럼 목록·반올림 자릿수·실행 결과는 `02_london/docs/DAILY_CONVERSION_PLAN.md`, 스크립트는 `02_london/src/01_hourly_to_daily.py`, 결과 파일은 `02_london/data/preprocess/day_london.csv` 참고(연도별 분리본은 `02_london/data/processed/`). 이 문서는 "왜 그 규칙을 골랐는지"에 대한 근거를 남기는 용도로 유지한다.

## 확정된 원칙

**집계 규칙(연산 방식)은 워싱턴과 동일하게 유지한다.** 컬럼별 스케일·인코딩이 달라도 "무엇을 계산하는가"(합계/평균/고정값/최악등급-최빈값)는 워싱턴 규칙서를 그대로 따른다.

**컬럼 값(인코딩)은 원본 그대로 사용하고, 워싱턴 체계로 리매핑하지 않는다.** 예: `weather_code`를 워싱턴의 `weathersit`(1~4)로 변환하지 않고, 런던 원본 코드(1, 2, 3, 4, 7, 10, 26) 그대로 집계한다. 이렇게 하면 나중에 다른 기간의 런던(또는 같은 출처의) 데이터가 추가로 들어와도, 코드 매핑표를 다시 손댈 필요 없이 같은 규칙을 그대로 재사용할 수 있다 — **전처리 최소화가 목적**.

## 컬럼별 최종 규칙

| 런던 컬럼 | 규칙 유형(워싱턴과 동일) | 구체적 방법 |
|---|---|---|
| `cnt` | 합계형 | 시간별 합계 |
| `t1`, `t2` | 평균형 | 시간별 단순평균 |
| `hum`, `wind_speed` | 평균형 | 시간별 단순평균, **소수 2자리 반올림으로 확정**(워싱턴의 소수 6자리는 정규화(0~1) 스케일 전제였기 때문에 따르지 않음) |
| `season`, `is_holiday`, `is_weekend` | 상수형 | 하루 중 고정값 그대로 사용 (실측 확인: 730일 전부 하루 내 값 1개, 워싱턴과 동일 성질) |
| `weather_code` | 컨디션등급형 | **워싱턴과 같은 규칙**: 하루 24시간 중 가장 나쁜(코드값이 큰) 등급이 4시간 이상이면 그 값 채택, 아니면 최빈값. **코드값은 원본(1,2,3,4,7,10,26) 그대로 사용, 워싱턴 1~4 스케일로 리매핑하지 않음** |

## weather_code를 원본값 그대로 써도 되는 근거

Kaggle 공식 데이터셋(hmavrodiev/london-bike-sharing-dataset) 문서 기준 코드 의미:

| 코드 | 의미 |
|---|---|
| 1 | Clear |
| 2 | Scattered clouds / few clouds |
| 3 | Broken clouds |
| 4 | Cloudy |
| 7 | Rain / light rain shower |
| 10 | Rain with thunderstorm |
| 26 | Snowfall |

7개 코드가 이 순서(1→2→3→4→7→10→26)로 실제 날씨 악화 순서와 일치함을 확인했다(맑음→구름→비→뇌우→눈). 값 자체는 원래 서수로 설계된 코드는 아니지만, 이 데이터셋에 등장하는 7개 값에 한해서는 "코드가 클수록 날씨가 나쁘다"는 워싱턴 규칙의 전제가 그대로 성립하므로, 별도 리매핑 없이 원본값에 직접 규칙을 적용해도 된다.

## season 인코딩 차이 (참고, 리매핑하지 않음)

런던 `season`은 0=spring, 1=summer, 2=fall, 3=winter (0-based)로, 워싱턴의 1=봄~4=겨울(1-based)과 인덱스 시작점이 다르다. 위 원칙에 따라 **리매핑하지 않고 런던 원본 값(0~3) 그대로** 사용한다. 두 데이터셋을 나중에 합쳐서 비교할 일이 생기면 그때 별도로 처리한다.

## 확정·실행 완료 (업데이트)

- `hum`, `wind_speed` 반올림: 소수 2자리로 확정
- `workingday` 파생: `is_weekend==0 AND is_holiday==0` → 1. 워싱턴 731일 전체와 대조해 정확히 일치함을 확인 후 확정
- `casual`/`registered`는 런던 원본에 없어 생성하지 않음 — `cnt`만 합계형 규칙 적용 (변경 없음)
- 24시간 미만 날짜: 730일 중 34일 (서머타임 등). 결측과 구분하는 로직 대신, 실제 관측 시간 수를 `n_hours_observed` 컬럼으로 그대로 남기는 방식으로 처리(플래그 대신 원값 노출)
- 시간별→일별 변환 스크립트(`02_london/src/01_hourly_to_daily.py`) 작성·실행 완료. 원본 17,414행 → 일별 730행. **`2016-09-02`는 원본에 아예 없어 결과에도 행이 없음**(별도 발견 사항, `DAILY_CONVERSION_PLAN.md` 참고)

## 남은 미결 항목

- weather_code 최빈값 동률("더 나쁜 코드 우선") 처리가 실제로 몇 건 발생했는지 아직 집계 안 함
- `day_london.csv`에 대한 데이터 품질 점검(워싱턴의 01_data_quality_check.py 상당)은 아직 미착수
- `2016-09-02` 완전 결측을 이후 분석에서 어떻게 다룰지(보간/제외/그대로) 결정 안 됨
