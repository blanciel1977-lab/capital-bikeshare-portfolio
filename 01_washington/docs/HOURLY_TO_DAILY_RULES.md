# 시간별 → 일별 변환 규칙서 (자전거 대여 데이터 전용)

이 문서는 `bike_sharing_hour.csv`(시간별)를 `day.csv`(일별)와 대조해 **실제로 계산·검증한 결과**를 바탕으로 정리한 집계 규칙이다. 추측이 아니라 731일 전체에 대해 여러 집계 방식(sum/mean/max/min/mode/first/last)을 직접 돌려 day.csv와 일치하는 비율을 확인한 뒤 확정했다 (검증 방법은 6절 참고). 워싱턴(Capital Bikeshare) 데이터로 검증했으며, 같은 컬럼 구조를 쓰는 런던 등 다른 자전거 대여 데이터셋에도 그대로 적용할 것을 전제로 작성했다.

## 1. 적용 범위

- 시간별 관측치를 하루 단위로 합쳐 일별 데이터셋을 만드는 모든 자전거 대여 데이터에 적용
- 컬럼명이 다르더라도 **아래 4가지 컬럼 유형 중 무엇에 해당하는지**로 판단해 적용한다
- 이 문서는 규칙만 정의한다. 실제 코드 구현·데이터 수정은 별도 작업이며, 이 문서 작성 시점에는 어떤 데이터도 수정하지 않았다

## 2. 컬럼 유형별 집계 규칙

### 2-1. 상수형 (달력·구분 변수)

**해당 컬럼(워싱턴 기준)**: `season`, `yr`, `mnth`, `holiday`, `weekday`, `workingday`

**규칙**: 집계하지 않는다. 하루 안에서 값이 바뀌지 않는 변수이므로, **그날의 값을 그대로 가져온다** (구현상 `first`나 `mode` 둘 다 결과가 같지만, "집계"가 아니라 "고정값 복사"로 이해해야 한다).

**검증 방법 및 주의**: 새 데이터셋에 적용하기 전, `groupby(날짜)[컬럼].nunique()`로 하루 안에 값이 정말 1개뿐인지 먼저 확인한다. 만약 하루 안에 값이 여러 개라면(예: 날짜 경계 처리 오류, DST 등) 이 규칙을 적용하면 안 되고 원인을 먼저 파악해야 한다.

### 2-2. 평균형 (연속 측정값)

**해당 컬럼(워싱턴 기준)**: `temp`, `atemp`, `hum`, `windspeed`

**규칙**: 시간별 값의 **단순 평균(mean)**. 결측 시간이 있어도 있는 시간만으로 평균 낸다(2절 4항 참고).

**검증 결과**: 워싱턴 데이터 731일 전체(100%)가 이 방식으로 정확히 재현됨(오차범위 1e-4 이내).

### 2-3. 합계형 (건수·카운트)

**해당 컬럼(워싱턴 기준)**: `casual`, `registered`, `cnt`

**규칙**: 시간별 값의 **합계(sum)**. `cnt = casual + registered`라는 항등식은 일별·시간별 모두에서 성립하므로, 셋 중 하나를 다른 둘로부터 계산해도 되지만 데이터 누수 위험이 있으니 모델링에는 셋을 함께 넣지 않는다(기존 워싱턴 프로젝트 README 참고).

**검증 결과**: 731일 전체(100%) 정확히 일치.

### 2-4. 컨디션 등급형 (순서형 범주 — 예: 날씨등급)

**해당 컬럼(워싱턴 기준)**: `weathersit`

**규칙 (사용자 확정)**:
1. 하루 24시간 중 **가장 나쁜(값이 큰) 등급이 4시간 이상** 나타나면 → 그 최악 등급을 그날의 값으로 채택
2. 조건 1을 만족하지 않으면 → **최빈값(mode)**을 채택
3. 최빈값이 동률(두 등급의 출현 횟수가 같음)일 경우 → **더 나쁜(값이 큰) 등급을 우선** 채택 (사용자에게 재확인 필요 — 3절 참고)

**검증 결과 및 한계**: 워싱턴 데이터에서 순수 최빈값(mode)만으로는 632/731일(86.5%)만 일치했다. "최악 등급 4시간 이상" 조건은 사용자가 이번에 확정한 보정 규칙이며, **아직 731일 전체에 대해 재검증하지 않았다** — 새 데이터셋에 적용하기 전 반드시 이 규칙으로 다시 계산해 일치율을 확인할 것을 권장한다.

## 3. 확정이 필요한 사항 (미결)

- weathersit 최빈값 동률 처리 방식: "더 나쁜 등급 우선"으로 문서에는 기재했으나, 사용자로부터 명시적 확답을 받지 못했다. 실제 코드 구현 전에 재확인 필요
- "최악 등급 4시간 이상" 규칙을 워싱턴 731일 전체에 적용했을 때 실제 일치율이 얼마나 개선되는지 아직 미검증

## 4. 반올림 규칙

- 평균형 컬럼(`temp`, `atemp`, `hum`, `windspeed`)은 **원본 day.csv와 동일하게 소수 6자리**를 유지한다.
- 합계형 컬럼(`casual`, `registered`, `cnt`)은 정수이므로 반올림 이슈가 없다.
- 상수형·컨디션등급형 컬럼은 정수/범주이므로 반올림 대상이 아니다.
- **주의**: 시간별 원본 값 자체가 정규화(0~1 스케일)되어 있으므로, 평균을 낸 뒤 원본 스케일로 역변환하는 경우 반올림 순서(역변환 전/후 중 언제 반올림하는지)에 따라 미세한 차이가 생길 수 있다. day.csv는 **정규화된 값을 평균 낸 뒤** 반올림하는 방식과 일치했다.

## 5. 결측 시간 처리 (사용자 확정)

**규칙**: 24시간 중 일부가 결측이어도, **있는 시간만으로 그대로 집계한다** (원본 day.csv가 실제로 이 방식이었음 — 예: 2012-10-29는 1시간 데이터만 있어도 그 1시간만으로 평균·합계를 냈다).

**단, 아래 신뢰도 표시를 함께 남긴다** (원본 day.csv에는 없지만, 이 프로젝트에서 추가로 권장하는 QA 절차):

| 필드 | 정의 |
|---|---|
| `n_hours_observed` | 그날 실제 관측된 시간 수 (0~24) |
| `coverage_flag` | `complete`(24시간), `partial`(12~23시간), `incomplete`(12시간 미만) |

이렇게 하면 집계값 자체는 원본 방식과 동일하게 유지하면서도, 분석 시 결측이 심한 날(예: 워싱턴의 2012-10-29, 2011-01-27 등)을 필터링하거나 별도 주의하며 다룰 수 있다. 실제 임계값(12시간 등)은 데이터셋 특성에 따라 조정 가능하며, 이 문서에서는 워싱턴 데이터 검증 과정에서 나온 결측 패턴(폭풍·재난일에 결측 집중)을 참고해 잠정 제안한 값이다.

## 6. 검증 방법 (재사용용 절차)

새 데이터셋에 이 규칙을 적용하기 전, 다음 순서로 반드시 재검증한다.

1. 시간별 파일을 날짜(`dteday`)로 `groupby`
2. 컬럼 유형별 후보 집계 함수(sum/mean/max/min/mode/first/last)를 전부 계산
3. 일별 파일의 실제 값과 대조해 **몇 일이 정확히 일치하는지** 세기 (연속형은 `np.isclose`로 오차범위 허용, 그 외는 완전 일치)
4. 100% 일치하는 방식이 있으면 그 규칙 채택, 없으면(예: weathersit처럼) 보정 규칙을 설계하고 다시 검증
5. 일치하지 않는 날짜가 있으면 목록을 남겨 원인(재난·이벤트·기록 오류 등)을 확인 — 통계적으로 이상한 날일 가능성이 높다 (워싱턴 데이터의 경우 결측·불일치가 실제 허리케인·폭설 등 이벤트와 연동됨)
