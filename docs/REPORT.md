## 4. 모델링: 어떤 요인이 총 대여건수(cnt)에 영향을 주는가

### 4.1 데이터 누수(leakage) 사전 검증

`cnt = casual + registered`로 정의된 값이므로, 이 두 컬럼을 입력 변수에 포함하면 모델이 항등식을 그대로 학습해 RMSE=0, R2=1.0000이 나온다(`outputs/model/linear_regression_result.md` (1)절 참고). 이는 유효한 예측이 아니므로, 이후 모든 모델링에서 `casual`, `registered`를 입력에서 제외했다.

### 4.2 데이터 분할

`day.csv` 731건을 train 80%(584건) / test 20%(147건)로 분할(random_state=42, 고정). 입력 변수는 `season, yr, mnth, holiday, weekday, workingday, weathersit, temp, atemp, hum, windspeed` 11개.

### 4.3 모델 성능 비교

| 순위 | 모델 | RMSE | MAE | R2 |
|---|---|---|---|---|
| 1 | **XGBoost (튜닝 후)** | **626.23** | **428.57** | **0.9022** |
| 2 | XGBoost (기본값) | 655.49 | 446.11 | 0.8928 |
| 3 | 랜덤포레스트 | 669.10 | 429.28 | 0.8884 |
| 4 | 선형회귀 | 831.29 | 617.39 | 0.8277 |

(`outputs/model/model_comparison.png`, 각 모델의 상세 결과는 `outputs/model/*_result.md`. 이 수치는 `src/` 스크립트를 이 저장소의 `requirements.txt` 버전으로 그대로 재현한 값이다. XGBoost/matplotlib 버전에 따라 소수점 단위 편차가 있을 수 있으나 모델 순위와 결론은 바뀌지 않는다.)

**지표 판단 기준**
- RMSE: 오차 제곱평균의 제곱근. 큰 오차(이상치)에 민감
- MAE: 오차 절댓값 평균. 모든 오차를 동등하게 취급
- R2: 목표변수 전체 변동 중 모델이 설명하는 비율

**해석**: 선형회귀는 세 지표 모두 최하위로, 기온-대여량 관계의 비선형 패턴(고온에서 대여량이 꺾이는 현상)을 포착하지 못한다. 트리 기반 앙상블(랜덤포레스트, XGBoost)이 이런 비선형·상호작용 패턴을 더 잘 학습해 RMSE를 19~23% 낮췄다.

### 4.4 XGBoost 하이퍼파라미터 튜닝

GridSearchCV(5-fold CV, scoring=neg_root_mean_squared_error)로 `n_estimators, max_depth, learning_rate, subsample` 총 162개 조합을 탐색했다.

- 최적 조합: `learning_rate=0.05, max_depth=3, n_estimators=300, subsample=0.8` (CV RMSE 650.99)
- 기본 하이퍼파라미터(`max_depth=4, subsample=1.0`) 대비 test RMSE가 655.49 → 626.23로 개선됨
- 결론: 트리 깊이를 4→3으로 줄이고 `subsample=0.8`로 매 트리마다 데이터의 80%만 사용하도록 하여 트리 복잡도를 제한한 조합이, 584건 규모의 데이터에서 기본값보다 일반화 성능이 더 좋았음

## 5. 모델 재사용성 검증: yr 변수의 한계와 보정

### 5.1 문제

`yr`은 2011/2012 두 범주뿐인 이진 변수로, 중요도 34%로 최상위였다. 이는 "날씨/계절의 진짜 효과"가 아니라 "그 2년간 서비스가 이만큼 성장했다"는 사실을 모델이 암기한 결과이며, **미래 연도(2013년 이후)로 일반화할 수 없다.**

### 5.2 보정: detrend 후 재학습

`cnt_relative = cnt / (해당 연도 평균 cnt)`로 변환해 "그 해 평균 대비 상대지수"를 목표변수로 삼고, `yr`을 제외한 뒤 날씨/계절/요일 변수만으로 재학습했다(`outputs/model/detrend_analysis_result.md`).

- 성능: RMSE 0.1539 / MAE 0.1099 / R2 = 0.8247 (상대지수 단위이므로 절대치 모델과 직접 비교 불가)
- 변수 중요도: season(0.261) > temp(0.239) > atemp(0.213) > weathersit(0.114) — 날씨/계절 계열 합산 약 82.7%
- 이 구조는 연도와 무관하게 재사용 가능한, 진짜 "날씨/계절이 수요에 미치는 영향" 패턴으로 해석할 수 있다

### 5.3 실무 적용을 위한 2단계 파이프라인 제안

```
최종 예측 cnt = ① 연도별 기준선(baseline) x ② 날씨/계절 상대지수
```

1. **기준선 추정**: 과거 성장 추세(2011→2012 +64%) 또는 등록회원 증가율 등 외부 지표로 미래 연도의 평균 대여량을 별도 추정 (시간에 따라 계속 갱신 필요)
2. **상대지수 예측**: 본 보정 모델로 날씨/계절/요일 조건에 따른 "기준선 대비 배율" 예측 (연도가 바뀌어도 재사용 가능)
3. **결합**: 두 값을 곱해 최종 대여량 산출

## 6. 최종 결론

1. **핵심 영향 요인은 "서비스 성장 추세 + 계절/기온"**이다. 다만 "성장 추세(yr)"는 해당 데이터셋 특유의 정보로 미래에 재사용할 수 없고, **재사용 가능한 진짜 요인은 계절(season)·기온(temp/atemp)·날씨등급(weathersit)**이며 이들을 합치면 detrend 모델에서 82%의 설명력을 차지한다.
2. **날씨가 나쁠수록, 기온이 낮을수록 대여량이 뚜렷하게 감소**한다(박스플롯·상관관계·중요도 분석에서 일관되게 확인).
3. **요일·공휴일·근무일 변수는 상대적으로 영향이 작다.** 계절/날씨 대응 전략(우천 시 대체 서비스, 혹한기 이용 유도책 등)이 요일별 프로모션보다 효과적일 것으로 판단된다.
4. **모델 선택**: 예측 정확도가 목적이면 XGBoost(튜닝)를 채택하되, "왜 그런가"를 설명해야 하는 보고서에는 선형회귀 계수(방향성)와 detrend 분석(재사용 가능한 요인)을 함께 제시하는 것이 타당하다.
5. **분석의 신뢰성 확보 과정**: casual/registered로 인한 데이터 누수, yr의 일반화 불가 문제를 모두 사후 검증을 통해 발견하고 보정했다는 점이, 단일 지표(R2)만 보고 끝내지 않고 모델의 실제 재사용 가능성까지 검증했다는 것을 보여준다.
